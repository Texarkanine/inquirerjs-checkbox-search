## LESSONS LEARNED

**From reflection (inlined):**

- **`yoctocolors-cjs` checks `hasColors` at module-load time** via `tty.WriteStream.prototype.hasColors()`, not per call. `FORCE_COLOR` / `NO_COLOR` apply only in a new Node process, not after modules load. With `NO_COLOR` set in this test environment, `colors.*` returns plain strings, so ANSI escape assertions against default theme output are not viable.
- **Styling assertions:** Prefer the existing **custom theme override** pattern (e.g. `theme: { style: { description: (t) => '**' + t + '**' } } }`) when you need to prove styled output; default “cyan” wiring is better implied by theme tests than by fragile ANSI checks.
- **`git stash` for triage:** Stash → run failing tests on clean HEAD → `git stash pop` is a quick way to prove failures are pre-existing rather than regressions.

**Million-dollar takeaway:** If style tests are designed around theme overrides from the start, you avoid vague default-theme ANSI checks that cannot pass under `NO_COLOR`. The renamed bottom-placement test plus custom-style tests is the right split.
