## REQUIREMENTS

1. Record the merge-base with `main` and the pull request head in the same job. Each side's image is built from that tree's `demos/Dockerfile`.
2. For each tape, write the GIF, the text record, and the PNG frames. Add `Output` lines on a temporary copy of the tape. Write text records and frames to a scratch folder. Do not upload the frames.
3. Fingerprint each demo two ways: the normalized text record, and the frame-text PNG sequence. Consecutive identical frames collapse to one run. A run held for fewer than 8 frames is left out of the compared fingerprint.
4. Verdicts are NEW, REMOVED, CHANGED, SAME, UNSTABLE, and NOISY. NEED_FRAME_RETRY is the internal signal that asks the workflow to record again.
5. Retry rule, as amended on 2026-10-08 and tightened on 2026-10-09:
   - A text mismatch is CHANGED on the first comparison.
   - A frame mismatch is CHANGED only when each side's retry matches that side's first frames and the two sides still differ.
   - One agreeing pair does not erase a difference that another pair recorded.
   - A text record that disagrees with itself across re-recordings of the same commit is UNSTABLE.
   - A frame disagreement that a side does not repeat is NOISY.
6. The comment keeps today's expand and collapse. Shadow mode adds one verdict line. Switch the comment only after dependency-bump pull requests come out SAME.
7. Replace the hidden `Sleep 1s` after `node examples/….js` with `Wait+Screen /Search:/`.
8. Amend the README GIFs on a release pull request only when a demo is CHANGED. If a committed reference is required, commit text fingerprints. Never commit frame hashes. That switch waits on requirement 6.
9. The shadow step finishes, exits 0 with a visible verdict, and leaves the frame PNGs on the host. Process-wide `TMPDIR` stays off the scratch bind mount. The container command does not create `/tmp/vhs-frames` before `vhs` runs.

Constraints that held through the reworks: VHS is the version `demos/Dockerfile` pins. `--output` accepts only `.gif`, `.webm`, and `.mp4`. Both sides of a comparison use the same runner and the same kind of image. A Dockerfile or VHS-version edit is CHANGED only when the fingerprints change. Durations are not compared. Demos show only what the tapes exercise. Feature pull requests get no bot commits. UNSTABLE and NOISY exit 0 during shadow so the required check stays green.

Chromium's profile and the frame directory both come from the process temp dir. That temp dir on the bind mount is what turned a three-minute failure into the hang. Do not retry that commit.
2. Keep the process temp dir off the scratch mount. Copy frames out of container `/tmp/vhs-frames` with a named container, `chmod` so the mode-0600 PNGs are readable, and `docker cp` / `docker rm -f` in a `finally`. Cap the shadow step at 20 minutes.

## LESSONS LEARNED

- GIF bytes differ on every recording because frame timing and the palette vary. The text record is taken once per tape command, so a skipped animation frame does not change it. The frame-state sequence is sampled on a timer and can skip a short state when the runner is busy.
- The GIF-only path in `scripts/generate-demo.js` must not import `scripts/demo-fingerprint.ts`. That import would make today's demo scripts depend on Node's type stripping.
- Generator `--scratch` and fingerprint `--scratch` are different directories.
- VHS v0.10 renames its frame directory onto the Output path and ignores a failure. A destination that already exists, or a destination on another filesystem, leaves the frames directory empty. Cleanup then deletes the PNGs that were still in the temp dir.
- Do not point the container `TMPDIR` at the scratch bind mount. VHS prints `File:` before it starts ttyd and Chromium, and that is where the six-hour hang stopped.
- Dropping a one-frame state that sits between two copies of the same screen must not merge those copies into one run. Collapse first, then filter.
- A retry that only checks "the sides still disagree" treats runner jitter as a product change. Each side has to repeat itself.
